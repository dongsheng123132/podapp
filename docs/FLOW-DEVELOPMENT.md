# 请帮我串一条泊舟工作流

我有一个小需求，想一键跑完。你不用写代码、不用建工程、不用打包 ——
**只输出一份 JSON**，把我机器上已经装好的动作按顺序串起来。

## 先看我有哪些动作

在泊舟里点「接到 AI」把 MCP 桥接上，然后问 `tools/list`；
或者让我把浮舱里那几个程序舱的动作 ID 念给你。

**只能用已经装了的动作。** 你猜一个不存在的动作 ID，跑之前就会被拦下并告诉我
「第 N 步引用了没装的动作」—— 不会装坏任何东西，但也跑不起来。

## 输出这个形状

```json
{
  "spec": "podapp/flow@0.1",
  "id": "my.idcard",
  "name": "身份证三步",
  "steps": [
    { "action": "app.annotate.image.crop", "input": { "image": "$in" } },
    { "action": "app.qrfix.code.replace",  "input": { "poster": "$prev" } }
  ]
}
```

两个记号，只有这两个：

| 记号 | 意思 |
|---|---|
| `$in` | 我拖进浮舱的那个东西（一般是第 1 步用） |
| `$prev` | **上一步产出的那个产物的路径**（不是内容） |

## ⚠️ `$prev` 只在上一步**恰好产出 1 个产物**时有定义

这条最容易踩，而且踩了之后错得很明显：

```
第 1 步 切 3×3  → 产出 9 张
第 2 步 用 $prev → 失败：「上一步产出了 9 个产物，$prev 只在恰好 1 个时有定义」
```

**不会替你挑一张。** 挑了的话，你会拿到一条「跑成功了但结果只有九分之一」的流程，
而那个错要等人看结果才发现。

「产出了几个」以**产物账本**为准（真的落盘了几个），不是数返回值里的字段。
所以：

- 开了 `zip: true` 的步骤会多产出一个压缩包 → 变成 2 个 → `$prev` 就没定义了
- 只查询不产出的步骤（比如列个清单）产出 0 个 → 下一步也用不了 `$prev`

**怎么绕**：让上一步只产出一个（比如 `rows:1, cols:1`、别开 `zip`），
或者干脆拆成两条流程，中间那步的产物从收件箱里拿。

## 六条规矩

1. **`$prev` 不能出现在第 1 步** —— 它前面没有步骤。这是最常见的错（照模板改忘了第一行）。
2. **记号必须是整个值。** `"image": "$prev"` 对；`"image": "$prev.png"` 不生效，
   原样当普通字符串。不做字符串拼接是故意的 —— 那种写法看着能用而含义模糊。
3. **`input` 可以省略**（有些动作不要参数），但写了就必须是对象，不能是数组。
4. **最多 30 步。** 一个小需求不该有三十步；真到那个规模，该做成程序舱了。
5. **声明了要确认的动作会停下来等我点头**，不是跑完再问。你不用管这个，
   浮舱会处理 —— 但**别试图绕开它**（比如把危险动作拆成几个小步骤）。
6. **步与步之间传的是产物引用**，不是图片内容。所以上一步必须真的产出**恰好一个**
   产物，下一步才有 `$prev` 可用（见上面那节）。

## 出错了怎么办

跑之前的检查会**一次说完所有问题**，不是报一条改一条。把它原样贴回来给我，
我按每条改。常见的三类：

- `第 N 步引用了没装的动作 xxx` → 换一个我装了的，或者告诉我该装哪个程序舱
- `第 1 步用了 $prev` → 第一步改成 `$in`
- `第 N 步的 input 必须是对象` → 别写成数组

## 现成的案例照着改最快

仓库里 `examples/flows/` 有几份**会被 CI 验**的案例（官方 Pod 改了动作 ID
它们就会红）。挑一份形状最接近的改，比从零写省事，也不会引用到不存在的动作。

## 什么时候不该用工作流

- **需要新的能力**（现有动作里没有那个动词）→ 那要做程序舱，看 `POD-DEVELOPMENT.md`
- **需要循环、分支、重试** → 工作流是一条直线，没有这些。要那些就是程序舱。
- **一步就够** → 直接跑那个动作，别包一层。

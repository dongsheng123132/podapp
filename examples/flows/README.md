# 官方案例流程

**这些不是展示品，是会被 CI 跑的东西。** `crates/podapp-flow/tests/example_flows.rs`
把 `pods/` 全部装进隔离家目录，然后对这里每一份跑一遍 `check`。

所以：官方 Pod 谁改了动作 ID 或者改了必填参数，这里会**当场红**。

## 为什么案例和 Pod 同仓库

我一开始建议把案例放去 `podapp-protocol/`（规范那个仓库）。**跑了一轮之后改主意了**：
案例引用的是**官方 Pod 的动作 ID**，而那些 Pod 在这个仓库里。放到另一个仓库，
动作改名时 CI 抓不到，案例就变成一份「看起来对、抄了就错」的示范 —— 而 AI 会照着抄。

`podapp-protocol/` 该放的是**规范本身**和不依赖任何具体 Pod 的模板。

## 为什么只 check，不 run

跑起来要真图、真会话、真数据，而那些不该进仓库。`check` 验的是
「动作在不在、必填参数给没给、`$prev` 用得对不对」——那正是案例最容易腐坏的部分。

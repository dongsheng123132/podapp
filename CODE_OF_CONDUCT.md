# PodApp Community Code of Conduct

## Our commitment

PodApp is building an open language for human–AI interaction. The community should be usable by
people with different backgrounds, abilities, identities, languages, experience levels, and views.

Contributors, maintainers, signatories, and participants commit to making project spaces
welcoming, safe, and focused on the work.

## Expected behavior

- Be respectful, specific, and patient.
- Critique ideas, designs, and code without attacking people.
- Assume good intent while still addressing concrete harm.
- Make room for newcomers and explain project-specific context.
- Respect privacy, consent, attribution, licences, and security boundaries.
- Disclose relevant conflicts of interest.
- Accept correction, repair mistakes, and stop behavior when asked.

## Unacceptable behavior

- Harassment, threats, intimidation, stalking, or sustained disruption.
- Discrimination or derogatory comments about personal identity or background.
- Sexualized language, imagery, or unwelcome attention.
- Publishing private information, credentials, or private communications without permission.
- Impersonation, fraudulent signatures, or misleading claims of project endorsement.
- Deliberately unsafe instructions, malware, secret collection of user data, or attempts to bypass
  project security controls.
- Retaliation against a person who reports a concern in good faith.

## Scope

This code applies in repositories, issues, pull requests, discussions, reviews, events, and other
spaces where someone represents PodApp or its community.

Technical disagreement is welcome. Repeatedly ignoring a stated boundary, derailing discussion, or
using "debate" to target a person is not.

## Reporting and enforcement

For ordinary technical disagreements, use the relevant issue or pull request. For conduct concerns,
contact a repository maintainer privately through GitHub. If no private route is visible, ask a
maintainer to provide one without posting sensitive details publicly.

For security vulnerabilities, follow [`SECURITY.md`](./SECURITY.md) instead.

Maintainers will review reports in good faith, limit disclosure to people needed for the response,
and consider context, severity, pattern, and impact. Possible responses include clarification,
warning, content removal, temporary restriction, or permanent removal from project spaces.

Anyone enforcing this code must disclose a conflict of interest and step aside when they cannot
review a report impartially.

## Attribution

This is a project-specific code of conduct informed by widely used open-source community standards.
It is published under the repository's documentation terms.

# PodApp 社区行为准则

## 我们的承诺

PodApp 正在建立一种开放的人机交互语言。社区应该欢迎不同背景、能力、身份、语言、经验与观点
的人参与。

贡献者、维护者、宣言签署者和所有参与者，都应共同维护一个友善、安全、专注于工作的空间。

## 期待的行为

- 尊重他人，表达具体，保持耐心；
- 批评观点、设计和代码，不攻击个人；
- 默认善意，同时认真处理已经造成的具体伤害；
- 给新参与者留下空间，并解释项目特有的上下文；
- 尊重隐私、同意、署名、许可证与安全边界；
- 主动披露相关利益冲突；
- 接受纠正、修复错误，并在被要求时停止越界行为。

## 不可接受的行为

- 骚扰、威胁、恐吓、跟踪或持续扰乱讨论；
- 针对个人身份或背景的歧视、贬损；
- 性暗示内容或不受欢迎的关注；
- 未经许可公开私人信息、凭据或私下沟通；
- 冒充身份、伪造签名、虚构项目背书；
- 故意提供危险指令、传播恶意软件、秘密收集用户数据或绕过项目安全控制；
- 报复善意报告问题的人。

## 适用范围

本准则适用于仓库、Issue、Pull Request、Discussion、评审、活动，以及任何代表 PodApp 或其社区
的场合。

我们欢迎技术分歧；反复无视明确边界、故意带偏讨论，或以“辩论”为名针对个人，不属于正常
技术讨论。

## 报告与处理

一般技术分歧请在对应 Issue 或 Pull Request 里讨论。行为问题请通过 GitHub 私下联系仓库
维护者；如果暂时看不到私密渠道，可以先请维护者提供，不要公开敏感细节。

安全漏洞请改按 [`SECURITY.md`](./SECURITY.md) 报告。

维护者会善意审查报告，只向处理所需人员披露信息，并综合考虑上下文、严重程度、重复模式与
实际影响。处理方式可能包括澄清、警告、删除内容、暂时限制或永久移出项目空间。

负责处理的人如存在利益冲突，应主动说明并回避。
